## 1. 차례 (차례·말 풀이)

1. 연락 한 통이 들어와서 원래 쓰던 곳이 바뀌기까지
2. 일마다 모으고 새것은 설정 파일로
3. 받은 그대로, 빠짐없이 가져오기
4. 정리한 기록은 어떻게 짜여 있나
5. 어느 일인지 알아보는 법
6. 대표에게 보이는 화면
7. 단추를 누르면 원래 쓰던 곳까지
8. 나가는 메일은 어떻게 허락받나
9. 정기 작업이 조용히 멈추지 않게
10. 새 시스템으로 넘어가기
11. 다른 회사에 시스템을 만드는 순서

## 2. 전체 개념도: 여섯 걸음

**모은다 → 가른다 → 제자리에 둔다 → 돌아본다 → 한다 → 남긴다**

가운데에 **Mac mini (24시간 켜 둠)**이 있고, 여섯 걸음이 모두 이 기계를 거쳐 돈다. 사람은 옆에서 **결정**만 하고, 밖으로 나가는 건 **"보내"** 한마디로 허락한다.

```
        1 모은다 ──▶ 2 가른다 ──▶ 3 제자리에 둔다
            ▲                          │        사람 → 결정 → [보내] → 메일
            │       [ Mac mini ]       │
            │       24시간 켜 둠        ▼
        6 남긴다 ◀── 5 한다 ◀──── 4 돌아본다
```

| 인스타 DM | |

- 화면 표시 예시: "이번 달 들어 지금까지 **1,437건**"

### 2) 가른다 (밤사이)

- **클로드**가 모인 것을 읽고 네 갈래로 나눈다.
  - ☑ 할 일
  - 📅 일정
  - 🔖 참고
  - 🗑 버림
- 슬라이드 문구: "밤[사이 클로드가 가른]다." `[추정]`

### 3) 제자리에 둔다

- 📅 캘린더
- ☑ 할 일 목록
- 📊 진행표
- **슬랙 #채널**: 연차 신청, 비용 신청
- **보리 (AI 비서)**: 슬랙의 연차 신청·비용 신청을 받아 정리한다.
- 슬라이드 문구: "[…]비서 「보리」가 [연차·]비용 신청을 받아 정리한다."

### 4) 돌아본다

- ☀ **아침**: 아침 페이지로 하루를 연다.
- 🌙 **23:00**: 매장 채널 7개를 모은 **일일 보고**가 온다.
- 슬라이드 문구: "아침 [페이지로] 하루를 연다." / "[…]는 매[장 채널 7개를 모]은 일일 보고가 온다."

### 5) 한다

| 도구 | 역할 |
|---|---|
| 클로드 코드 | 작업 실행 (코드·파일) |
| Codex | 작업 실행 (코드) |
| Aside | 브라우저 작업 |
| Higgsfield | 영상 제작 |

- 슬라이드 문구: "Aside가 브라우[저를 …], [Higgsfi]eld가 영상을 만든다."

### 6) 남긴다

- 📖 **위키**: 배운 것을 남긴다.
- 📋 **규칙**: 번호가 붙은 규칙 목록 (1, 2, 3, 4 …)
- 슬라이드 문구: "배운 [것은 위키에] 남기고, [규칙으로 …]" `[추정]`

### 사람의 자리

- 사람 → **결정**(선택지 고르기) → **[보내]** 버튼 → ✉ 메일
- 슬라이드 문구: "[…]고 밖으로 [나가는 건] "보내" 한마디."
- 요점: 기계가 준비하고, **바깥으로 나가는 것만 사람이 허락**한다.

## 3. 시연: 새 승인 페이지 (`desk.imiwork.com`)

대표가 매일 보는 화면. Aside 브라우저로 열어 시연했다.

### 탭 구성

| 탭 | 표시된 수 |
|---|---|
| 오늘 | |
| 할 일 | 43 |
| 정하실 것 | 0 |
| 답장 | 10 |
| 한 일 | |
| 점검 | 3 |
| 프로젝트 | 7 |
| 교훈 `[추정]` | 1 |
| 개발 보드 | 9 |

### 카드 한 장의 구조 (할 일 탭)

각 카드는 같은 틀로 되어 있다.

1. **제목** (예: "대표이사 급여 금액 정하기")
2. **상태 표시**: `오래됨` · `기계가 보기엔 아직 할 일` · `기계가 못 하는 일이에요` / `기계가 해 둔 것 있음`
3. **요약**: 지금 어디까지 왔는지 한두 문장
4. **권함**: 기계가 권하는 다음 행동과 그 이유
5. **기계가 본 것**: 근거가 된 파일과 줄 번호 (예: `README.md 23행`, `completed-todos.md`에 완료 표시 없음)
6. **▼ 기계가 해 본 것 – 못함 / 초안**: 기계가 시도한 내용과 결과
7. **단추**: 상황에 맞는 선택지
8. **말 남기기**: 고칠 말을 남기면 다음 회차에 그 말까지 읽고 다시 한다.
9. **▶ 할 일 줄 원문 / 원문 열기 →**: 원래 기록으로 이동

### 단추 예시

| 카드 종류 | 단추 |
|---|---|
| 금액을 정해야 하는 일 | 금액 정했어요 · 급여 안 정할래요 · 미루기 |
| 답장 초안이 있는 일 | 답장 보냈어요 · 이미 조율 끝났어요 · 답 안 해요 · 미루기 |
| 피드백 요청 | 피드백 보냈어요 · 문제없다고 답했어요 · 안 할래요 · 미루기 |
| 프로젝트 | 계속 진행 · 멈춤으로 · 목록에서 빼기 |
| 점검(규칙 붙이기) | 붙여요 · 빼요 |
| 물음 | (선택지 두 개, 예: "그 PC에서 판을 올릴게요" · "그대로 둬요 — 또 나면 봐요") |

- 답장 카드에는 기계가 쓴 **메일 초안**(일정·비용·대상 항목에 빈칸)이 들어 있다.
- "고칠 말은 「말 남기기」로 — 다음 회차에 그 말까지 읽고 다시 해요. **보내는 것은 원문을 열어 직접.**"
- 연락을 보내는 일은 사람이 직접 하는 일이라 기계가 하지 않는다 (카드에 "연락은 [대표]가 직접 보내는 일이라 기계가 못 해요"라고 표시).

### 오늘 탭

- 오늘 / 내일 / 모레 일정이 맨 위에 보인다.
- **새로 적기**: "떠오른 것을 적으면 메모 더미에 그대로 쌓이고, 밤에 정리돼 다음 날 카드로 붙어요."
  - 입력칸 안내: "떠오른 것을 막 적어 주세요. 여러 개면 줄을 바꿔서."
  - [남기기] 버튼
- 화면 상단 안내: 누른 것은 새 기록 장부에 적히고, 할 일 파일·메일·일정 같은 **원본은 안 바뀐다**(그림자 판 / 진짜 판 구분). `[추정]`

### 프로젝트 탭

- 예: "시스템 개념도 — 붙여 나가기" (진행 중, 마지막 손댄 날 표시)
  - 설명: "업무 시스템을 개념도대로 다시 세운다. 가운데(중앙)를 먼저 세우고, 새 일과 새 정보가 거기에 붙게 한다."
  - 권함: "계속 진행 — 상태와 어긋나지 않아요"
  - ▶ 메모 N / ▶ 누르면 어떻게 되나
- 예: "어드밴스드 과정 — AX 캠프 다음 단계 과정을 본격적으로 만든다"

### 점검 탭

- 규칙 붙이기 제안: "권함 붙여요 — 추측입니다(붙이면 같은 검사를 다시 돌려 **통과할 때만 적용**돼요)"
- 물음 카드 예시:
  - "그 PC에서 판을 올리시겠어요?" — 기계가 본 것: `backlog.md`에 사무실 PC의 메일 도구가 옛 판이라 초안(`--draft`)이 안 만들어진다는 항목이 'open'으로 남아 있고, `resolved.md`에는 없다.
  - "무인 잡에 장기 토큰을 쓸까요, 만료되면 알림만 받을까요?"
- 요점: 기계가 **근거(파일·줄 번호)**와 **추측인지 여부**를 함께 밝힌다.

## 4. 1장 들어가며: 연락 한 통이 들어와서 원래 쓰던 곳이 바뀌기까지

(`sot-concept.vercel.app`, 다음 화면: "메일 한 통")

### 흐름도

```
원래 쓰던 곳 ──▶ ① 가져오기 ──▶ ② 정리한 기록
     ▲                                  │
     │                                  ▼
⑥ 정해 둔 방법 ◀── ⑤ 화면 ◀────── ④ 알아보기
```

범례:
- ■ 사람이 허락한 것
- □ 「자동」은 규칙대로 한 것
- □ 「AI」는 AI가 정한 것
- ---- 막힌 길

### 본문

> 아침에 메일함을 열면 밤사이 온 메일이 수십 통 쌓여 있습니다. 대표는 그중 어느 메일이 어느 거래처의 답장인지 다 기억하지 못합니다.

이미커피의 구로 로스터리(원두를 볶아 다른 카페에 납품하는 곳)는 지난주에 거래처 카페로 다음 달 원두 물량 견적을 보냈습니다. 오늘 아침 그 카페 사장님이 견적대로 받겠다는 답장을 보내왔습니다. 시스템은 이 답장이 원두 납품 이야기인 줄 알아보고, 할 일 목록의 「견적 답 기다리기」에 체크합니다. 그리고 대표의 화면에 원하는 납품 날짜를 묻는 답장 초안을 띄웁니다. 대표는 초안을 읽고 보내기 단추를 누릅니다.

이 사이트에서 대표는 이 시스템을 쓰는 이미커피·DBT의 대표입니다. 본문의 숫자와 있었던 일은 이 시스템을 실제로 만들며 겪은 일이고, 거래처와 사람은 이름 대신 역할로 씁니다. 아래 초록 단추를 누르면 한 장면씩 넘어갑니다.

## 핵심 정리

1. **원본(원래 쓰던 곳)은 건드리지 않고**, 받은 그대로 빠짐없이 가져와 정리한 기록을 따로 만든다.
2. 모으기(15분마다) → 가르기(밤사이, 클로드) → 제자리(캘린더·할 일·진행표·슬랙 비서) → 돌아보기(아침 페이지, 23:00 일일 보고) → 하기(클로드 코드·Codex·Aside·Higgsfield) → 남기기(위키·규칙)의 고리.
3. 가운데에는 **24시간 켜 둔 Mac mini** 한 대.
4. 사람은 **결정과 허락**만 한다. 밖으로 나가는 메일은 "보내" 한마디, 또는 원문을 열어 직접 보낸다.
5. 카드마다 **기계가 본 것(근거)**, **기계가 해 본 것**, **권함**, **추측 여부**를 밝힌다.
6. 사람이 남긴 말("말 남기기")은 다음 회차에 반영되고, 배운 것은 위키와 규칙으로 쌓인다. 규칙은 같은 검사를 통과할 때만 붙는다.
